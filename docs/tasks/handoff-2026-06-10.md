### 3. Deferred SRS tech debt (non-blocking)

From the final holistic code review (commit `12fccd9` resolved Critical/Important items; these were the "Minor / Consider" findings):

- **Persist store versioning** — `stores/progressStore.ts` has no `version` field or `migrate` function. The kana migration works for the v0→v1 transition but provides no path for future schema changes. Add `version: 1` and move the rehydrate logic into a proper `migrate(state, version)` function before the next schema change is needed.
- **`getDueCount` selector cost** — `app/(tabs)/_layout.tsx:20` recomputes `Object.values().filter().sort()` on every store mutation. Fine at current scale; memoize on `srsItems` once the pool grows.
- **`MatchingGame` helper dedup** — the kana-lookup-then-grade pattern is repeated 4 times (~12 lines each). Extract a `gradeKanaCard` helper to avoid bug-multiplier risk if the payload shape changes.
- **`ReviewSession` shuffle** — `components/srs/ReviewSession.tsx` uses `sort(() => Math.random() - 0.5)` which is biased. `lib/srs/adapters.ts` has a proper Fisher-Yates `shuffle` — extract it to `lib/srs/utils.ts` and reuse.
- **`SpeedChallengeQuestion` field duplication** — `character`/`prompt` and `romaji`/`correctAnswer` are populated to the same values. Either dedupe or convert to a discriminated union.
- **Distinct unsafe casts** — `lib/srs/adapters.ts:42,72` use `as KanaPayload` / `as VocabPayload` after a `.filter()`. Use a type-guard predicate (`.filter((p): p is SrsItem & { payload: KanaPayload } => p.payload.kind === 'kana')`) instead.
